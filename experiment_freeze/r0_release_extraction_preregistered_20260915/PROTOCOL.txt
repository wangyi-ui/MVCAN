============================================================
2. FROZEN SCIENTIFIC DEFINITION
============================================================

Sparse labels determine semantic direction.

Frozen directional U_cycle determines action validity.

The final iterative mechanism is:

Q_t
-> R_t
-> A(T_relation, U_cycle)
-> Q_{t+1}
-> R_{t+1}

The final method is NOT a module stack.

The final method is NOT a single weighted joint loss.

The final optimization is an alternating two-phase process:

Phase A:
Utility-conditioned relation semantic action

Phase B:
Native MVCAN consolidation / representation update

During release extraction the final method must NOT be rewritten as:

L_total = L_native + lambda * L_relation

No extraction stage may change this scientific contract.

6. ACTION-SPACE GENERALIZATION CONTRACT
============================================================

For balanced generator/verifier partitions, define the intended action count:

If V is even:

S(V) = C(V, V/2)

If V is odd:

S(V) = 2 * C(V, floor(V/2))

Required known cases:

- V=6 -> S=20
- V=5 -> S=20
- V=2 -> S=2

The next Generic Contract stage must define and validate the corresponding
ordered generator/verifier action constructor for arbitrary supported V.

For Caltech-6V, the generic constructor must reproduce both the frozen set of
20 action identities and their exact ORDER. Set equality alone is insufficient.
The meaning of every action index s must remain scientifically identical. Any
implementation representation change requires an explicit compatibility map
that itself proves exact frozen ordering and logical action identity.

18. R7 — EQUIVALENCE VALIDATION LEVELS
============================================================

R7 must bind and pass Levels 0-8:

LEVEL 0 — Tensor Contract Parity
Verify shape, dtype, sample IDs, view order, K, action dimensions, and other
dataset-derived boundaries.

LEVEL 1 — Utility Exact Parity
For frozen Caltech, require new U_cycle to equal the frozen logical
representation and exact logical hash.

LEVEL 2 — Semantic Target Exact Parity
Require PredRelation_true bitwise exact and relation_balance_weights_true exact
with matching logical hash.

LEVEL 3 — Semantic Loss / Gradient Parity
Using the same model state and batch, compare loss, per-view reductions,
denominator, query gradients, missing anchor gradient, and detached U/target/
balance. Floating comparison may use only a tolerance frozen before mismatch.

LEVEL 4 — Single Optimizer-Step Parity
With identical initial model, optimizer state, batch, and seed, separately prove
one semantic-action update and one native-consolidation update produce
equivalent parameters.

LEVEL 5 — Single-Epoch Schedule Parity
Use identical epoch order, Phase A, refresh behavior, and Phase B; require model-
state parity.

LEVEL 6 — 20-Epoch Seed20 Exact Replay
Require final sample IDs exact, final predictions exact, and final model
aggregate hash exact.

LEVEL 7 — Multi-Seed Exact Replay
For seeds 20, 30, and 50 require final predictions exact and final model hashes
exact. Only after sealed prediction may GT be loaded; ACC, NMI, and ARI must then
be exact.

LEVEL 8 — Closed-Loop Dynamics Parity
If the dynamics audit is retained, compare D_A, D_B, G_U, and D_U_UNI against
frozen F0-A1 evidence. Ordinary release training does not need to store 41
trajectory snapshots.
